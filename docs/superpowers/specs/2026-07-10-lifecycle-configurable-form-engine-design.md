# 工程项目生命周期与受约束动态表单引擎设计

- 状态：已确认增强设计方向
- 方案：C/A - 固定核心生命周期 + 强后台管理操作系统 + 受约束可视化工作流
- 初始日期：2026-07-10
- 更新日期：2026-07-11
- 文档版本：1.1
- 适用范围：招投标、项目管理、审计、资料、结算中心及后台设置

## 1. 背景与问题

当前系统已经具备项目、审计、资料、结算及部分字段配置能力，但业务规则仍主要分散在各页面和表单中。随着项目进入不同阶段，系统容易提前要求用户填写尚未产生的信息，或者允许用户选择与工程流程相悖的状态。

典型问题包括：

1. 项目尚未竣工或未验收合格，却出现送审、一审、二审等选项。
2. 项目处于合同签订阶段，却要求上传竣工验收证明或审计报告。
3. 同一字段在项目、审计、资料和结算模块重复录入，口径不一致。
4. 用户模型偏单角色，无法准确表达一人多岗、项目负责人和审核责任。
5. 字段配置主要解决显示、排序和必填，缺少条件规则、版本、权限和项目级覆盖。

## 2. 设计目标

系统以项目生命周期为主轴，以业务事件驱动表单、资料、待办和模块联动。

目标：

1. 固定工程项目主生命周期和核心阶段准入规则。
2. 支持一个用户拥有多个岗位角色，并在不同项目中承担不同项目角色。
3. 支持按企业、项目类型和单一项目配置阶段问卷。
4. 当前阶段只展示当前能够确认的信息，不把未来资料计为缺失。
5. 核心字段保持统一语义，供项目、审计、资料、结算和报表共同使用。
6. AI 只负责提取和建议，关键金额、条款和阶段变更必须经人工确认。
7. 建设独立的后台管理操作系统，使每个生命周期阶段的表单、资料、审批、条件和自动动作均可配置。
8. 提供可视化拖拽式工作流设计器，同时保护合同、验收、送审、审计、定案和归档等核心业务顺序。
9. 将合同、竣工验收证明、审计报告等文档识别真正接入业务表单和待办，而不是停留在文本摘要或演示界面。

## 3. 非目标

系统不建设完全自由且无保护的 BPM 平台。即使后台管理能力增强，也不允许管理员：

1. 任意删除系统核心生命周期阶段。
2. 通过配置绕过竣工验收、审计和归档的核心准入条件。
3. 编写 JavaScript、SQL 或任意执行脚本。
4. 将所有核心业务数据存入无类型 JSON 或纯 EAV 结构。
5. 让 AI 自动确认金额、自动推进项目阶段或覆盖人工确认数据。

管理员可以在核心阶段内部增加子流程、表单、判断、审批、资料、通知和自动任务，也可以配置核心阶段之间的进入条件；但不能删除核心阶段、颠倒受保护的业务顺序或解除法定和财务控制点。

## 4. 核心设计原则

1. **流程固定，问卷可配**：生命周期和核心门槛由系统保护，字段、布局和补充资料允许配置。
2. **事件驱动**：合同签订、验收合格、送审、一审完成等事件驱动后续任务和资料要求。
3. **一次录入，多处复用**：项目主数据、合同和金额字段由统一数据源提供。
4. **当前阶段最小必要信息**：没有走到的阶段不展示、不必填、不计缺失。
5. **配置有版本**：发布新模板不能静默改变历史记录。
6. **权限到动作和字段**：不仅控制菜单，还控制数据范围、操作、字段和文件。
7. **所有自动结果可解释**：金额计算、状态建议和 AI 识别均展示来源和过程。
8. **设计与运行分离**：管理员编辑的是草稿版本，生产项目只运行经过校验和发布的不可变版本。
9. **强后台、低前台负担**：复杂性集中在管理员终端，一线用户只看到与本人、当前项目和当前阶段有关的问题。
10. **核心保护、局部自由**：后台允许充分配置，但系统始终阻止不符合工程管理事实顺序的工作流。

## 5. 生命周期状态机

### 5.1 主生命周期

```text
机会发现
→ 投标登记
→ 待开标
→ 已中标
→ 已签订合同
→ 已进场施工
→ 施工中
→ 已竣工待验收
→ 验收合格
→ 资料准备中
→ 已送审
→ 一审中
→ 一审完成
→ 二审中 / 政府审计中
→ 二审完成
→ 最终定案
→ 收付款及质保期管理
→ 已结案归档
```

投标未中标、项目终止、验收不合格等情况作为分支结果，不直接删除历史项目。

### 5.2 生命周期规则矩阵

| 当前阶段 | 关键输入 | 阶段完成事件 | 下一阶段准入条件 | 自动动作 |
| --- | --- | --- | --- | --- |
| 投标登记 | 招标人、项目名称、开标时间、招标文件 | 投标登记完成 | 基础信息完整 | 生成待开标提醒和资料目录 |
| 已中标 | 中标金额、中标日期、中标通知书 | 中标确认 | 中标结果已确认 | 创建项目主档案，生成合同待办 |
| 已签订合同 | 合同主体、金额、日期、付款条款、合同附件 | 合同确认 | 合同金额大于 0，合同主体完整 | 提取付款条款，生成履约资料清单 |
| 已进场施工 | 进场日期、项目负责人、施工联系人 | 进场确认 | 已签订合同 | 生成施工阶段待办 |
| 施工中 | 进度、签证、付款申请、过程资料 | 竣工申报 | 工程已完成 | 生成验收准备清单 |
| 已竣工待验收 | 竣工日期、验收安排 | 验收结果确认 | 验收结果已填写 | 合格进入资料准备；不合格生成整改待办 |
| 验收合格 | 验收日期、验收证明 | 验收通过 | 验收结果为合格且证明齐全 | 开放送审问卷和结算资料清单 |
| 已送审 | 送审金额、送审日期、送审单位、资料 | 送审确认 | 已验收合格 | 同步审计看板，生成一审跟进待办 |
| 一审完成 | 一审单位、负责人、审定金额、报告 | 一审结果确认 | 一审报告或确认记录齐全 | 计算核减额和核减率，开放二审问卷 |
| 二审完成 | 二审单位、负责人、审定金额、报告 | 二审结果确认 | 二审资料完整 | 生成定案待办 |
| 最终定案 | 定案金额、日期、定案资料 | 定案确认 | 最终金额已确认 | 更新结算基数、发票和收付款待办 |
| 已结案归档 | 归档目录、质保金状态、结案确认 | 归档确认 | 必归档资料完整，高风险待办关闭 | 锁定核心数据，保留版本和操作日志 |

### 5.3 状态变更规则

1. 正向推进必须通过阶段准入校验。
2. 回退阶段必须填写原因，并记录回退前后状态、操作者和时间。
3. 禁止跨越核心阶段；确需补录历史项目时使用“历史项目初始化”，逐步确认已有事实。
4. 验收不合格时不得显示送审状态选择，系统只生成整改和复验任务。
5. 阶段完成后，核心事实字段默认锁定；有权限的用户通过更正流程修改。

### 5.4 核心流程保护与可配置边界

采用方案 A：核心生命周期受保护，阶段内工作流高度可配置。

| 配置对象 | 管理员能力 | 系统保护 |
| --- | --- | --- |
| 核心阶段 | 修改名称说明、配置进入条件、配置角色和表单 | 不可删除、不可改变受保护顺序 |
| 阶段内子流程 | 新增、删除、拖拽排序、建立分支和回路限制 | 必须有明确开始、结束和超时处理 |
| 条件判断 | 配置且、或、非及条件组 | 禁止脚本执行和无限循环 |
| 审批节点 | 配置审批人、会签、或签、驳回和转办 | 高风险节点不能无审批人直接通过 |
| 表单节点 | 选择表单模板、字段权限、必填和锁定 | 核心语义字段不能被删除或改型 |
| 资料节点 | 配置资料类型、份数、版本和必填条件 | 未来阶段资料不得提前计为缺失 |
| 自动动作 | 生成待办、提醒、目录、记录和计算结果 | 不能自动确认金额或自动完成高风险阶段 |
| AI 识别节点 | 选择识别模板、目标字段和置信度阈值 | 正式写入前必须经过人工确认 |

受保护的关键顺序至少包括：中标后才能确认合同、合同后才能进场、竣工后才能验收、验收合格后才能送审、审计结果确认后才能定案、归档前必须完成必归档资料检查。

## 6. 角色与权限模型

### 6.1 三层身份

| 层级 | 示例 | 用途 |
| --- | --- | --- |
| 岗位角色 | 招投标员、审计员、财务、行政、经理、资料员 | 决定模块和业务动作权限 |
| 项目角色 | 项目负责人、经办人、审核人、协作人 | 决定具体项目的数据范围和责任 |
| 系统角色 | 系统管理员 | 管理账号、模板、字典、权限和系统设置 |

行政岗位不自动获得系统管理权限；经理岗位不等同于项目负责人。

### 6.2 权限计算

```text
最终权限 = 多岗位角色权限并集
         ∩ 数据范围
         ∩ 当前项目角色权限
         ∩ 当前生命周期阶段允许动作
         - 显式禁止权限
```

显式禁止优先于允许。用户不需要频繁切换角色，系统在“我的工作”中合并其所有授权任务，并显示当前操作所依据的角色。

### 6.3 角色权限矩阵

| 角色 | 默认数据范围 | 主要职责 | 受限动作 |
| --- | --- | --- | --- |
| 招投标员 | 本人及被授权投标项目 | 机会、投标、开标、中标移交 | 不确认审计金额和收付款 |
| 项目负责人 | 负责或参与项目 | 合同确认、进场、施工、验收准备 | 不确认财务到账和最终审定金额 |
| 审计员 | 被分配审计项目 | 送审、一审、二审、定案资料和进度 | 不修改原始合同金额 |
| 财务 | 被授权结算项目 | 发票、应收、实收、付款、质保金 | 不独立改变工程验收结果 |
| 资料员 | 被授权项目 | 资料收集、分类、版本和归档 | 不确认业务金额和阶段结论 |
| 行政 | 被授权行政范围 | 通讯录、基础组织信息、行政协作 | 默认无系统配置权限 |
| 经理 | 授权范围或全公司 | 查看、督办、复核、高风险确认 | 不直接替代经办事实录入 |
| 系统管理员 | 全系统 | 账号、角色、模板、字典和系统设置 | 不因系统权限自动获得业务确认权 |

小型公司允许同一人兼任经办和复核，但系统必须提示职责重叠，并保留完整日志。金额确认、付款确认、阶段回退和归档可配置为必须二次确认。

## 7. 动态表单引擎

### 7.1 模板继承

```text
系统核心模板
  → 企业生命周期模板
    → 项目类型模板
      → 单一项目覆盖
```

运行时优先级：单项目覆盖 > 项目类型模板 > 企业模板 > 系统核心模板。

系统核心模板保存生命周期所需的语义字段和准入规则。企业和项目只能在允许范围内覆盖标签、说明、排序、布局、补充字段、角色权限及更严格的资料要求。

### 7.2 字段定义

每个字段至少包含：

| 属性 | 说明 |
| --- | --- |
| semanticKey | 稳定语义标识，发布后不可随意修改 |
| label | 用户可见名称 |
| type | 文本、金额、日期、人员、单位、单选、多选、文件等 |
| stageKey | 所属生命周期阶段 |
| dataSource | 手填、项目带出、合同带出、系统计算、AI 建议 |
| requiredRule | 必填条件 |
| visibleRule | 显示条件 |
| editableRule | 可编辑条件 |
| allowedRoles | 可见和可编辑角色 |
| validation | 格式、范围、交叉字段校验 |
| optionGroup | 业务字典来源 |
| formula | 受支持的安全计算公式 |
| evidenceType | 需要关联的资料类型 |
| aiMapping | AI 提取目标及置信度阈值 |
| reporting | 是否用于查询、统计和导出 |
| sensitivity | 普通、敏感、脱敏展示 |

### 7.3 支持的规则

第一阶段只支持可视化、安全且可解释的规则：

1. 显示或隐藏字段、分组和后续问题。
2. 设置必填、只读、默认值和自动带出。
3. 执行白名单公式，如金额加减乘除、比例和日期间隔。
4. 要求上传指定资料。
5. 阶段准入校验。
6. 生成待办、提醒或复核任务。
7. 根据答案建议下一阶段，但不绕过确认。

规则示例：

```text
当“验收结果 = 合格”时：
- 显示“验收日期”和“验收证明”；
- “验收证明”设为必填；
- 允许进入“资料准备中”；
- 开放送审问卷。

当“验收结果 = 不合格”时：
- 隐藏全部送审字段；
- 禁止进入送审阶段；
- 生成整改和复验待办。
```

### 7.4 系统保护字段

以下核心字段不得删除、改变语义类型或取消核心校验：

1. 项目唯一标识和项目编号。
2. 建设单位、施工单位和合同主体。
3. 合同金额、合同日期和合同唯一标识。
4. 竣工验收结果、验收日期。
5. 送审、一审、二审、定案金额和日期。
6. 发票、收付款、质保金记录。
7. 当前生命周期阶段及阶段历史。

管理员可以调整这些字段的标签、帮助说明和布局，也可以提高必填要求，但不能降低系统核心门槛。

### 7.5 单项目覆盖

单项目配置支持：

1. 增加项目特有字段和资料类型。
2. 调整字段顺序、分组、说明和可见角色。
3. 将企业模板中的可选字段提升为必填。
4. 停用非核心的扩展字段。

单项目配置不得影响其他项目，不得取消核心字段、核心准入规则或已经发生的历史事实。

### 7.6 可视化工作流设计器

后台提供节点连线式工作流画布。管理员从左侧节点库拖入节点，在画布中连接业务路径，在右侧属性面板配置规则。

支持的节点类型：

1. 开始、结束和阶段进入节点。
2. 表单问卷节点。
3. 条件判断和多分支路由节点。
4. 单人审批、或签、会签和经理复核节点。
5. 资料上传与资料完整性检查节点。
6. AI 文档识别和人工确认节点。
7. 金额公式与日期计算节点。
8. 创建待办、通知、提醒和超时升级节点。
9. 写入业务记录和同步其他模块节点。
10. 子流程调用节点。

画布必须提供缩放、自动排版、小地图、撤销重做、复制节点、批量对齐、节点搜索、错误定位和只读版本对比。管理员不能直接在生产版本上编辑，必须先创建草稿。

### 7.7 条件规则编辑器

条件配置采用结构化规则，不允许编写 JavaScript 或 SQL。规则支持：

```text
当 [验收结果] [等于] [合格]
并且 [验收证明] [已上传]
则 [允许进入资料准备中]
否则 [生成整改与复验待办]
```

条件来源包括表单字段、项目主数据、角色、资料状态、日期、金额、流程执行结果和 AI 人工确认结果。支持条件组、且或关系、空值判断、包含判断、金额比较、日期间隔和字典值判断。

系统在保存和发布前检查：

1. 不可达节点和无出口节点。
2. 循环路径和缺少终止条件的回路。
3. 相互矛盾或永远成立的条件。
4. 被引用但已停用的字段、角色或字典项。
5. 无操作权限的审批人和权限死锁。
6. 违反核心生命周期保护规则的连线。

### 7.8 工作流运行机制

每个项目在进入阶段时创建工作流实例，并绑定工作流发布版本。运行中的实例不随后台草稿变化。

节点执行状态统一为：未到达、待处理、处理中、已完成、已驳回、已跳过、已超时、执行失败、已取消。每次执行保存输入、输出、操作者、开始结束时间、规则命中过程和错误信息。

自动节点必须具备幂等键和重试策略，避免重复创建待办、资料目录或财务记录。人工任务被撤回或阶段回退时，系统按补偿规则关闭后续未完成任务，但保留历史。

### 7.9 表单组件能力

除文本、数字、日期和选择项外，后台表单设计器还应支持：

- 金额输入并同步显示元、万元和中文大写；
- 单位、人员、项目、合同和资料引用；
- 文件上传、附件版本和资料分类；
- 表格子项、重复分组和付款节点明细；
- 地址、联系电话、百分比、税率和计算结果；
- 电子签名状态、确认声明和风险提示；
- AI 建议值、原文证据和人工确认状态；
- 只读业务摘要和跨模块引用信息。

字段支持按角色设置隐藏、只读、可编辑和脱敏。管理员预览时可以切换角色、项目类型、阶段和测试数据，看到一线用户的真实填写效果。

## 8. 模板版本与历史数据

模板状态为：草稿、已发布、已停用。

1. 每次发布生成不可变版本号。
2. 表单实例记录模板 ID、版本号和填写快照。
3. 新版本默认只应用于新进入该阶段的项目。
4. 在办项目迁移前必须展示影响范围、字段变化和缺失数据。
5. 删除扩展字段采用停用方式，历史值继续可查。
6. 迁移失败不得产生半完成状态，保留原版本并记录失败原因。
7. 所有发布、迁移和项目覆盖操作进入审计日志。

## 9. 后台管理操作系统

后台管理不再只是若干配置表格，而是面向系统管理员、业务管理员和审计管理员的独立操作终端。

### 9.1 信息架构

| 一级模块 | 核心能力 |
| --- | --- |
| 管理驾驶舱 | 配置健康度、待发布草稿、失败任务、AI 队列、数据异常和近期变更 |
| 组织与用户 | 用户、部门、岗位角色、项目角色、数据范围和账号状态 |
| 权限中心 | 模块、动作、字段、资料、项目范围和高风险二次确认策略 |
| 生命周期中心 | 核心阶段、阶段说明、进入退出条件、阶段负责人和保护规则 |
| 表单中心 | 表单设计器、组件库、字段语义库、模板继承和项目覆盖 |
| 工作流中心 | 可视化流程画布、规则、审批、自动动作、子流程和运行监控 |
| 资料规则中心 | 资料分类、阶段目录、必填条件、版本、归档和预览策略 |
| 业务字典 | 单位、人员、状态、项目类型、资料类型和可新增选项审核 |
| AI 识别中心 | 识别模板、字段映射、置信度、任务队列、人工复核和效果统计 |
| 集成与接口 | OCR、大模型、存储、通知和外部系统的连接配置及健康检查 |
| 发布与版本 | 草稿包、差异对比、模拟测试、审批发布、回滚和迁移任务 |
| 日志与诊断 | 配置日志、运行日志、错误追踪、接口调用和数据修复入口 |
| 系统设置 | 上传限制、编号规则、金额精度、通知策略和安全设置 |

### 9.2 三类可视化设计器

1. **生命周期设计器**：以受保护阶段轨道展示全局流程，允许配置阶段属性和阶段内子流程，不允许破坏核心顺序。
2. **表单设计器**：左侧组件库、中间表单画布、右侧属性和规则面板，支持拖拽分组、字段和资料组件。
3. **工作流设计器**：左侧节点库、中间连线画布、右侧节点条件属性，下方显示校验错误和测试轨迹。

三类设计器共享字段语义库、角色库、资料类型、业务字典和规则表达式，避免同一概念在不同后台页面重复定义。

### 9.3 配置作用范围

管理员创建配置时必须先选择作用范围：

```text
系统默认 → 企业全局 → 项目类型 → 指定项目
```

页面持续显示当前作用范围，防止管理员误把单项目配置发布到全公司。指定项目配置必须展示与上级模板的差异，并可一键恢复继承。

### 9.4 管理员角色分级

- 系统管理员：管理平台、账号、集成、发布和安全策略。
- 业务管理员：配置被授权模块的表单、流程、字典和资料规则。
- 审计管理员：查看全部配置变更、版本和运行日志，但不能直接修改生产配置。
- 项目配置员：只能为被授权项目增加扩展字段或提高资料要求。

### 9.5 沙箱模拟与发布

每次发布必须经过：保存草稿、自动校验、沙箱模拟、影响分析、发布审批和正式生效。

沙箱允许管理员选择项目类型、生命周期阶段、用户角色和测试答案，逐步运行流程，观察显示字段、条件命中、审批人、自动待办和资料要求。系统提供内置正向和反向测试案例，例如“未验收不能送审”“金额超过合同金额必须拦截”。

影响分析至少展示：受影响模板、项目数量、在办实例、字段变化、权限变化、待迁移数据和无法自动迁移的项目。高风险发布必须由另一名管理员或经理复核。

### 9.6 运行监控

后台应提供工作流实例监控图，显示项目当前节点、等待人员、停留时长、失败自动动作和超时情况。管理员可以重试失败的自动节点、转交人工任务或发起受控回退，但不能直接篡改已确认业务结果。

## 11. AI 文档识别落地设计

AI 识别是正式业务能力，不是聊天摘要或一次性 OCR。优先落地合同和竣工验收证明，再扩展审计、发票和付款资料。

### 11.1 识别范围

| 文档类型 | 重点提取字段 |
| --- | --- |
| 施工合同 | 合同名称编号、主体、金额、日期、工期、税率、付款条款、质保金、违约条款 |
| 中标通知书 | 项目名称、中标单位、中标金额、日期、工期和招标人 |
| 竣工验收证明 | 项目名称、参建单位、竣工日期、验收日期、验收结论、签章页 |
| 竣工结算书 | 送审金额、编制单位、日期和项目范围 |
| 一审二审报告 | 送审金额、审定金额、核减金额、核减率、审计单位、人员和日期 |
| 定案资料 | 最终审定金额、定案日期、确认单位和签章情况 |
| 发票 | 发票号码、日期、购销双方、税率、金额、税额和价税合计 |
| 收付款凭证 | 付款方、收款方、金额、日期、用途和流水号 |

### 11.2 识别处理流程

```text
上传文件
→ 文件分类和安全检查
→ OCR / PDF 文本提取
→ 条款和字段识别
→ 展示页码、原文、置信度和建议值
→ 用户逐项确认或修正
→ 写入合同和付款条款
→ 规则引擎生成付款节点和待办
```

上传后先进行文件类型、大小、恶意文件和重复文件检查。可复制文本 PDF 优先使用本地解析；扫描 PDF 和图片进入 OCR 与版面解析。大模型只接收必要文本片段和字段要求，输出符合 JSON Schema 的候选值。

### 11.3 人工复核界面

复核界面采用左右对照：左侧原文件及定位页，右侧候选字段、原文证据、置信度和业务校验结果。用户可接受、修改或拒绝单个字段，也可查看付款条款拆分过程。

金额、日期、单位和人员必须执行交叉校验，例如合同总额与大小写金额是否一致、付款比例合计是否合理、验收证明项目名称是否匹配当前项目。低置信度、冲突值和缺少证据的字段必须高亮，不允许批量静默写入。

### 11.4 识别模板后台

管理员可以按文档类型配置：目标字段、字段说明、示例、是否必提取、允许格式、字典映射、校验规则、置信度阈值、复核角色和写入目标。识别模板同样采用版本发布机制。

### 11.5 API 与供应商适配

AI 落地需要两类外部能力，系统必须通过适配器接口接入，不能把供应商协议写死在业务代码中：

1. **OCR 与版面解析 API**：处理扫描 PDF、表格、印章页和复杂版式，返回文字、坐标、页码和表格结构。
2. **支持结构化输出的大模型 API**：按指定 JSON Schema 提取合同条款和业务字段，并返回证据引用。

文件存储、病毒扫描和消息通知可继续使用现有能力；若现有能力不足，再作为独立集成补充。API 密钥只保存在服务端加密配置或环境变量中，绝不进入浏览器、代码仓库、操作日志或 Obsidian 记忆库。

### 11.6 识别效果指标

后台按文档类型统计任务量、成功率、平均耗时、字段接受率、字段修改率、低置信度率和人工复核时长。指标只使用真实识别任务，不生成演示数据。

AI 不得：

1. 静默覆盖人工确认数据。
2. 自动确认合同金额、审定金额或付款金额。
3. 自动推进生命周期阶段。
4. 无来源页和原文时写入正式数据。

AI 识别失败时保留原文件和任务记录，允许重试、切换供应商或完全人工录入，不能阻塞其他不依赖识别结果的业务操作。

后续按实际需求扩展中标通知书、验收资料、审计报告、发票和付款凭证识别。

## 12. 异常处理与可追溯性

1. 所有规则校验返回用户可理解的业务原因和解决入口。
2. 配置错误在发布阶段阻断，不把错误留给一线用户。
3. 阶段推进采用事务处理：阶段事件、表单锁定、待办和资料清单必须同时成功或全部回滚。
4. 操作日志保存人员姓名、账号、角色、项目、动作、前后值、时间和来源。
5. AI、公式和自动规则均保存输入、输出、版本和人工确认结果。
6. 集成密钥必须加密存储并只允许系统管理员更新，后台只能显示脱敏状态。
7. 工作流发布、回滚、实例人工干预和 AI 人工复核均写入不可篡改审计日志。
8. 自动任务使用重试、退避、死信队列和人工处置入口，避免失败任务无限循环。
9. 文件识别应设置租户、用户和文件级权限，临时解析文件按保留策略清理。
10. 删除模板、字段和工作流采用停用或归档，不直接物理删除仍被历史实例引用的配置。

## 13. 分期实施

### 第一阶段：后台规则底座（P0）

1. 生命周期状态机和阶段事件。
2. 多角色 RBAC、项目成员和数据范围。
3. 动态表单元数据、规则校验和核心字段保护。
4. 阶段准入、回退、二次确认和操作日志。
5. 工作流声明模型、运行实例和节点执行日志。
6. 草稿、校验、模拟、发布和版本回滚框架。

### 第二阶段：强后台与 AI 首批落地（P1）

1. 设置中心问卷编辑器。
2. 企业、项目类型和单项目模板继承。
3. 模板发布、版本和在办项目迁移。
4. 当前阶段资料清单和统一“我的工作”。
5. 将项目、审计和结算的现有关键表单迁入引擎。
6. 可视化工作流设计器、条件编辑器和运行监控。
7. 合同与竣工验收证明识别、人工复核和业务写入。
8. OCR、大模型和存储集成配置中心。

### 第三阶段：扩展识别与运营治理（P2）

1. 一审、二审、定案、发票和付款凭证识别。
2. 自动生成付款节点、资料清单和待办并展示计算过程。
3. 配置健康度、识别质量和工作流效率分析。
4. 在真实数据量和数据质量达标后建设预测与分析。

## 14. 验收标准

1. 合同签订阶段不展示验收、送审和审计字段。
2. 未竣工、未验收或验收不合格时，送审问卷不可见且接口拒绝推进。
3. 多角色用户在统一任务中心看到合并后的授权任务，不重复生成。
4. 用户只能查看授权范围内的项目和字段。
5. 单项目扩展字段不影响其他项目。
6. 模板新版本不改变历史表单实例和历史导出结果。
7. 模板发布前能够发现核心字段缺失、循环规则和权限死锁。
8. AI 提取结果必须展示来源页、原文和置信度，并经人工确认。
9. 阶段回退、金额更正和归档均有完整操作日志。
10. 当前阶段未产生的未来资料不计入资料缺失率。
11. 每个核心生命周期阶段均可绑定独立表单和阶段内工作流。
12. 管理员可以拖拽创建条件、审批、资料、AI、通知和自动动作节点。
13. 系统能够阻止删除核心阶段、颠倒受保护顺序和发布无效流程。
14. 工作流草稿不会影响正在运行的项目，新版本发布后历史实例仍可追溯。
15. 指定项目表单和流程覆盖不会影响其他项目，并可查看继承差异。
16. 沙箱能够模拟不同角色、项目类型和答案路径，并显示命中规则和生成任务。
17. 合同和验收证明识别结果能够定位到原文页和区域，逐字段人工确认后写入。
18. OCR 或大模型服务不可用时能够重试、切换供应商或回退人工录入。
19. API 密钥不出现在前端、仓库、日志、导出文件和记忆库中。
20. 后台能够查看失败节点、超时实例、待复核 AI 任务和配置发布历史。

## 15. 已确认决策

1. 采用固定生命周期和受约束动态表单引擎，不建设完全自由 BPM。
2. 一个用户可拥有多个岗位角色，并可在不同项目承担不同项目角色。
3. 系统管理员与行政岗位分离，项目负责人作为项目角色管理。
4. 支持企业、项目类型和单项目三级业务配置，系统核心模板作为不可绕过的底座。
5. 核心业务数据使用关系模型，扩展字段使用类型化动态值。
6. 模板采用发布和版本机制，历史实例不可被新配置静默修改。
7. AI 只提供建议，关键业务事实必须人工确认。
8. 采用方案 A：核心生命周期受保护，阶段内表单、条件、审批、资料、AI 和自动动作高度可配置。
9. 后台管理升级为独立操作系统，包含设计、模拟、发布、运行监控、集成和诊断能力。
10. 合同与竣工验收证明作为第一批正式落地的 AI 文档识别类型。

## 16. AI 实施前需要的外部输入

进入 AI 开发前，需要用户或企业提供以下资源，不应在设计阶段写入真实密钥：

1. OCR 与版面解析服务的供应商、接口地址、区域和测试凭据，或者确认采用本地 OCR 作为第一版。
2. 支持结构化 JSON 输出的大模型服务、模型名称、接口地址和测试凭据。
3. 已脱敏的真实合同、竣工验收证明、审计报告样本，用于定义字段和验收准确率。
4. 文件是否允许发送到第三方服务、允许发送的文档类型及数据保留要求。
5. 合同和验收证明每个目标字段的业务解释、必填规则和人工复核责任角色。

建议第一批至少准备 20 份版式有差异的脱敏合同和 20 份脱敏竣工验收证明。样本仅用于建立和验证识别模板，不进入演示数据或公开测试集。
