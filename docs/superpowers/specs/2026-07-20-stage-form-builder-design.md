# 阶段表单搭建器设计

- 日期：2026-07-20
- 状态：已确认，可进入实施计划
- 适用范围：桌面端后台设置、项目阶段表单运行端
替代范围：替代现有“审计字段配置”作为主要表单配置入口，并部分替代 2026-07-10 动态表单设计中“核心字段必须必填并阻断阶段推进”的规则

## 1. 背景

当前后台“审计字段配置”以字段列表和编辑弹窗为核心。管理员需要逐条理解字段标识、数据绑定、表格列宽和多个展示位置，才能间接推断最终填写表单的样子。

这个页面本质上是字段元数据维护工具，不是表单设计工具。它同时混合了三种不同任务：

1. 设计业务人员最终填写的阶段表单；
2. 维护系统字段类型和数据绑定；
3. 配置表格、看板和详情页的字段展示。

用户已确认后台应参考腾讯问卷的所见即所得体验，以“搭建表单”作为主要任务，而不是继续优化字段列表。

## 2. 设计目标

1. 业务配置人员无需理解技术字段即可完成阶段表单配置。
2. 表单最终填写效果在编辑过程中始终可见。
3. 字段添加、分组、排序、必填设置、填写角色和显示条件均可直接配置。
4. 所有字段，包括合同金额、验收结论和审定金额等核心业务字段，都允许业务配置人员自主设为必填或选填。
5. 系统继续保护字段类型、稳定标识和数据关联，防止业务事实被改型或错误绑定。
6. 草稿、预览、发布和版本记录形成完整闭环，历史表单不被新配置静默修改。
7. 第一版保持克制，不扩展为自由 BPM、多维表格或无代码数据库。

## 3. 非目标

- 不建设工作流画布、并行分支、审批节点或自动化动作。
- 不提供公式字段、跨表关联、任意脚本或 SQL。
- 不在第一版支持单项目单独覆盖表单。
- 不把表格列、看板卡片和详情页展示配置混入表单搭建器。
- 不允许业务配置人员修改系统字段的数据类型、稳定标识或数据绑定。
- 不生成模拟项目、模拟影响数量或看似真实的业务记录。

## 4. 信息架构

后台入口调整为：

```text
后台设置
  表单管理
    表单模板
    版本记录
  高级设置
    系统字段库
    列表与看板展示
```

第一版包含五个页面或主要界面：

1. **表单模板列表**：按公司标准、项目类型和阶段查看模板状态。
2. **阶段表单搭建器**：完成字段添加、分组、排序和业务属性配置。
3. **填写预览**：按指定填写角色检查真实运行效果，但不保存业务数据。
4. **发布确认**：展示业务语言变更摘要、适用范围和校验结果。
5. **版本记录**：查看历史版本，并通过复制历史版本重新发布实现回滚。

现有字段配置页改名为“系统字段库”，仅承担高级维护职责，不再作为主要表单配置入口。

## 5. 模板适用范围

第一版采用两级配置：

```text
公司标准模板 → 项目类型覆盖
```

- 公司标准模板定义所有项目类型默认使用的阶段表单。
- 项目类型模板继承公司标准模板，并可新增、排序字段或覆盖字段的业务属性；可以移除自身新增字段和无保护依赖的继承字段，但不能删除适用于该阶段的受保护核心字段。
- 第一版不提供单项目覆盖，避免配置碎片化和后续难以维护。
- 同一项目类型、同一阶段只能存在一个已发布生效版本。

## 6. 搭建器页面结构

采用已确认的三栏表单工作台。

### 6.1 顶部上下文区

固定显示：

- 当前模板名称和阶段；
- 作用范围：公司标准或具体项目类型；
- 继承来源；
- 当前草稿版本和发布状态；
- 预览填写和发布操作。

顶部上下文不得在编辑过程中隐藏，避免管理员发布到错误范围。

### 6.2 左侧添加区与表单大纲

左侧同时承担两个低成本任务：

1. 快速添加文本、金额、日期、选项、人员、附件、分组标题和说明文字；
2. 以表单大纲展示全部分组和字段，并直接切换每个字段的“必填/选填”。

左侧必填状态与右侧属性实时同步。系统字段和自定义字段均允许切换；新字段默认选填，避免新增字段意外阻断业务提交。

### 6.3 中间表单画布

画布直接呈现填写者看到的表单：

- 字段可点击选中；
- 字段和分组可拖拽排序；
- 支持新增、重命名和删除分组；
- 必填字段显示星号，选填字段明确显示选填状态；
- 系统字段显示“已有业务字段”标记，但不使用令人误解的“系统必填”标记；
- 空状态引导管理员添加字段或从公司模板继承。

键盘用户必须可以使用“上移、下移、移入上一分组、移入下一分组”完成与拖拽等价的排序。

### 6.4 右侧业务属性

右侧只显示业务人员能理解的设置：

- 问题名称；
- 填写提示；
- 必填或选填；
- 由谁填写；
- 什么时候显示；
- 选项内容，仅在单选或多选字段中显示。

字段类型、稳定标识、数据绑定、金额精度和索引等技术属性不在搭建器中出现。系统字段仅提示“类型和业务关联由系统维护，无需配置”。

## 7. 核心交互

第一版主路径固定为：

```text
添加字段 → 排序与设置 → 预览填写 → 发布变更
```

### 7.1 添加字段

- 点击组件时，将字段添加到当前选中分组的末尾。
- 拖拽组件时，在画布中显示明确落点。
- 添加成功后自动选中新字段，并打开右侧属性。
- 新字段默认选填。
- 使用系统字段时复用既有稳定字段，不创建重复语义。

### 7.2 排序与设置

- 左侧大纲和中间画布使用同一顺序状态。
- 在任一位置选中字段，另一位置同步高亮。
- 左侧可快速切换必填或选填；右侧显示同一状态。
- 所有字段都可由有权限的业务配置人员切换必填或选填。
- 受保护核心字段不能从其适用阶段模板中删除，但可以调整顺序并设为选填；其他系统字段在无业务依赖时可以从模板移除，字段定义仍不会被物理删除。

### 7.3 显示条件

显示条件使用业务语言规则，不允许脚本：

```text
当 [字段] [等于 / 不等于 / 包含 / 为空 / 不为空] [值] 时显示
```

第一版支持同一字段的多个条件，并允许选择“全部满足”或“任一满足”。循环依赖、引用已删除字段或不可达条件在发布前阻断。

只有当前可见且由当前角色填写的字段参与必填校验。因显示条件或字段权限而不可见的字段，不得阻断当前用户提交。

### 7.4 预览填写

- 管理员选择一个填写角色后进入预览。
- 预览执行必填校验、字段权限和显示条件。
- 预览不创建项目、阶段事件、表单提交或操作数据。
- 选填字段留空时允许通过预览校验。
- 页面明确标记“预览模式，不会保存业务数据”。

### 7.5 发布

发布前展示业务语言变更摘要，包括：

- 新增、移除和改名字段；
- 必填与选填变化；
- 填写角色和显示条件变化；
- 字段及分组顺序变化；
- 适用公司、项目类型和阶段；
- 根据真实项目计算的影响范围。

没有可验证的项目数据时，影响范围显示诚实空状态，不展示虚构数量。

## 8. 必填与阶段推进规则

本设计确认以下新规则：

1. `required` 是模板中的业务配置属性，不是系统字段的固定属性。
2. 所有字段，包括核心业务字段，均可配置为选填。
3. 选填字段为空时，表单允许提交，生命周期接口不得仅因该字段为空而阻断阶段推进。
4. 如果业务希望某字段阻断提交或推进，必须在当前模板版本中明确设为必填。
5. 系统仍保护核心字段的稳定标识、类型、单位、精度和数据关联。
6. 系统字段定义不可被物理删除；适用于当前阶段的受保护核心字段不能从模板删除，但可以设为选填。
7. 固定生命周期的阶段顺序继续生效，本次调整只取消“核心字段天然必填和空值天然阻断”的旧规则。

## 9. 权限

新增“业务配置人员”权限集合，由系统管理员授权。

业务配置人员可以：

- 创建和编辑模板草稿；
- 添加和排序模板字段，并移除自身新增字段或无保护依赖的继承字段；
- 设置必填、填写角色和显示条件；
- 预览并发布模板；
- 查看版本记录并复制历史版本。

业务配置人员不能：

- 修改系统字段类型、稳定标识和数据绑定；
- 删除系统字段定义；
- 扩大自身无权查看的数据范围；
- 修改固定生命周期阶段顺序。

第一版不增加独立发布审批流。具有发布权限的业务配置人员可在通过校验和确认变更摘要后直接发布，所有操作进入日志。

## 10. 版本与运行规则

### 10.1 草稿

- 编辑已发布模板时自动创建独立草稿。
- 修改自动保存，并显示保存状态。
- 并发保存使用版本号或 ETag；冲突时提示刷新和查看差异，不允许后提交静默覆盖先提交。

### 10.2 发布版本

- 每次发布生成不可修改的新版本。
- 同一作用范围和阶段只能有一个当前发布版本。
- 历史版本永久保留版本号、发布人、发布时间和变更摘要。
- 回滚通过复制历史版本形成新草稿并重新发布，不直接修改旧版本。

### 10.3 运行实例

- 项目进入某阶段并首次创建表单时绑定当时解析到的模板版本。
- 已开始填写或已经提交的表单继续使用原版本。
- 后续发布只影响之后新创建的阶段表单，不静默迁移在办实例。
- 每次提交保存 `templateVersionId`，保证历史数据可以按原结构解释。

## 11. 数据模型边界

建议使用以下核心对象：

```text
FormTemplate
  id, name, scopeType, projectTypeId, stageKey, status

FormTemplateVersion
  id, templateId, version, schema, changeSummary, publishedBy, publishedAt

FormSection
  id, title, description, sortOrder

FormFieldPlacement
  id, sectionId, fieldDefinitionId, label, helpText, required,
  fillerRoles, displayRule, sortOrder

FieldDefinition
  id, semanticKey, fieldType, valueType, binding, systemManaged

FormSubmission
  id, projectId, stageKey, templateVersionId, status, submittedBy, submittedAt

TypedFieldValue
  submissionId, fieldDefinitionId, typedValue, source
```

模板布局与业务属性可以采用声明式 JSON Schema 保存版本快照；正式业务值继续按类型保存，不能把所有值塞入无类型 JSON。

## 12. 配置与运行数据流

```text
业务配置人员打开模板
→ 读取公司标准或项目类型草稿
→ 添加、排序和设置字段
→ 自动保存草稿
→ 预览并执行发布校验
→ 确认变更摘要
→ 生成不可变发布版本
→ 项目首次进入对应阶段
→ 按项目类型 + 阶段解析当前发布版本
→ 创建绑定版本的阶段表单
→ 用户填写并提交类型化字段值
```

## 13. 接口建议

```text
GET    /api/admin/form-templates
POST   /api/admin/form-templates
GET    /api/admin/form-templates/{id}/draft
PUT    /api/admin/form-templates/{id}/draft
POST   /api/admin/form-templates/{id}/validate
POST   /api/admin/form-templates/{id}/preview
POST   /api/admin/form-templates/{id}/publish
GET    /api/admin/form-templates/{id}/versions
POST   /api/admin/form-templates/{id}/versions/{versionId}/copy

GET    /api/projects/{projectId}/stages/{stageKey}/form
PUT    /api/projects/{projectId}/stages/{stageKey}/form/draft
POST   /api/projects/{projectId}/stages/{stageKey}/form/submit
```

写接口使用幂等键和乐观锁。服务端重新校验模板版本、字段类型、填写权限和显示条件，不能只依赖前端校验。

## 14. 错误处理

发布前阻断以下问题，并定位到具体字段或分组：

- 字段名称为空；
- 同一表单重复使用互斥的字段定义；
- 显示条件引用已删除字段；
- 显示条件形成循环依赖；
- 填写角色不存在或已停用；
- 系统字段类型或数据绑定被篡改；
- 草稿基于过期版本并与他人修改冲突。

运行时：

- 模板无法解析时不回退到随意拼装的字段列表，显示明确错误并记录诊断信息；
- 选填字段留空不报错；
- 必填字段缺失时返回字段级错误；
- 无填写权限的字段既不显示也不接受接口写入；
- 重复提交返回同一业务结果，不创建重复记录。

## 15. 现有字段配置迁移

1. 将现有字段记录迁移为 `FieldDefinition`，保留稳定字段标识、类型和数据绑定。
2. 将当前 `visibleInForm=true` 的字段按所属阶段生成公司标准模板草稿。
3. 现有必填状态作为迁移草稿初值，但不自动发布。
4. 管理员必须在新搭建器中检查分组、顺序、必填状态和填写角色后手动发布。
5. `visibleInTable`、`visibleInCard`、`visibleInDetail` 和列宽继续归属独立展示配置，不进入阶段表单模板。
6. 迁移失败或语义不明确的字段进入待确认清单，不猜测字段含义。

## 16. 测试与验收

### 16.1 编辑体验

1. 点击或拖拽字段后，字段出现在正确分组并自动选中。
2. 左侧大纲、画布和右侧属性始终同步选中项、顺序和必填状态。
3. 任意字段均可切换必填或选填，新字段默认选填。
4. 系统字段不能修改类型、稳定标识和数据绑定。
5. 拖拽和键盘排序产生相同结果。

### 16.2 预览与权限

1. 预览按选择的填写角色显示字段。
2. 显示条件在预览中正确生效。
3. 选填字段留空可以完成预览校验。
4. 预览不创建任何项目、表单提交或阶段事件。
5. 无权限字段不能通过接口绕过页面写入。

### 16.3 发布与版本

1. 发布摘要准确列出字段、必填、角色、条件和顺序变化。
2. 无效配置明确定位并阻止发布。
3. 发布生成新版本且历史版本不可变。
4. 已开始填写的表单继续使用原版本。
5. 新阶段表单使用最新适用版本。
6. 复制历史版本后可形成新草稿并重新发布。

### 16.4 运行提交

1. 选填核心字段为空时允许提交并推进阶段。
2. 当前模板明确设为必填的字段为空时拒绝提交并定位字段。
3. 字段值按类型保存，金额、日期、人员和选项不能写入非法值。
4. 重复提交和并发保存不会创建重复记录或覆盖他人修改。
5. 没有真实项目数据时只显示空状态，不生成模拟记录或影响数量。

## 17. 已确认决策

1. 第一版只建设阶段表单搭建器，不合并表格、看板或工作流配置。
2. 采用腾讯问卷式三栏所见即所得布局。
3. 右侧属性只使用业务语言，技术属性移入系统字段库。
4. 左侧增加表单大纲，并可直接设置必填或选填。
5. 所有字段，包括核心字段，均由业务配置人员自主决定是否必填。
6. 选填字段为空不阻断表单提交和阶段推进。
7. 第一版模板范围为公司标准模板和项目类型覆盖，不支持单项目覆盖。
8. 业务配置人员可以预览并直接发布，不增加独立审批流。
9. 新发布版本不静默改变已开始填写的表单。
