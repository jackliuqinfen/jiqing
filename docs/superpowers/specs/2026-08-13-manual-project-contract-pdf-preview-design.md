# 手工创建项目旁置合同 PDF 预览设计

日期：2026-08-13  
状态：书面规格已确认，进入实施规划
适用范围：项目管理中的“手工创建项目”流程

## 1. 背景

当前项目建档入口把新建操作导向独立的合同复核工作台。手工通道仍会同步把整份合同按 300 DPI 转成逐页图片；长合同会产生明显等待，甚至超过反向代理超时时间。用户已经取消前端 AI/OCR 建档，希望所有项目都由员工对照合同原文手工填写。

本次调整恢复并保留现有四步新建向导的页面结构、字段顺序和操作习惯，只在右侧增加合同原文 PDF 在线预览。系统不再要求用户进入独立复核工作台，也不在该流程中启动 OCR 或全量页面转图。

## 2. 目标与不可变边界

### 2.1 目标

1. 新建项目继续使用现有四步向导：`基础信息 → 项目阶段 → 资料目录 → 确认生成`。
2. 在向导右侧展示合同原文，支持边看边填，不增加新的业务步骤。
3. PDF 首屏尽快可用；翻页时只加载当前页及相邻页，不等待整份合同处理完成。
4. 正式建档必须已保存合同原件，并由当前用户手工确认关键合同字段。
5. 正式生成项目、合同事实、证据关联和生命周期事件时，继续使用受保护的合同确认事务，不恢复普通项目新增接口。
6. 中断后可以继续填写并复用已经上传的合同，不要求重复上传。

### 2.2 不改变的内容

- 四个步骤的名称、顺序、上一步/下一步/确认生成行为不变。
- 为满足后端正式合同建档门禁，在“基础信息”中将建设单位、合同金额设为必填，并补充必填的付款条款输入；其余字段分组和校验保持不变。
- 编辑已有项目仍使用现有编辑弹窗，不显示合同预览面板。
- 项目编号仍由系统按现有规则生成。
- 普通新建项目的生命周期初始规则、资料目录初始化规则和权限规则不变。
- 已有正式项目、合同文件和历史复核记录不迁移、不删除。

### 2.3 本期不做

- 不提供系统 OCR、外部 AI Markdown 导入或 AI 字段建议入口。
- 不删除后端已有 OCR、识别任务和历史复核能力；它们仅不参与当前手工建档界面。
- 不重做项目管理列表、项目详情或已有项目编辑页。
- 不在浏览器一次性渲染全部 PDF 页面，也不在服务器为手工建档生成 300 DPI 逐页图片。
- 不支持在预览区直接批注、签章、编辑或合并 PDF。

## 3. 页面设计

### 3.1 总体布局

“手工创建项目”打开现有 `新建项目向导`。弹窗扩大为可用视口内的宽屏工作区：

- 左侧约 60%：完整承载现有四步向导，原有 DOM 顺序、字段和底部操作保持不变。
- 右侧约 40%：新增“合同原文”面板。
- 两侧分别滚动，翻阅合同不会把左侧表单滚离当前填写位置。
- 右侧面板可折叠；折叠后左侧占满可用宽度，恢复时保留页码和缩放比例。
- 可用宽度不足时，右侧默认收起为“查看合同原文”入口，点击后以右侧抽屉展示；不压缩或重排原表单字段。

右侧面板不会成为向导的新步骤，也不改变底部“取消、上一步、下一步、确认生成”的位置和语义。

### 3.2 合同未上传状态

右侧显示轻量空状态：

- 主操作：`上传合同 PDF`。
- 辅助说明：合同原件必须成功保存后才能确认生成正式项目。
- 仅接受 PDF 进入在线预览；格式或大小不合规时返回准确原因。
- 选择文件后立即上传。上传进度只覆盖右侧面板，不锁死左侧表单。
- 上传失败时保留所有已填字段，并明确提示“合同尚未保存”；用户可以重试或更换文件。

### 3.3 后端必填字段

“基础信息”步骤继续沿用现有表单布局，并按后端正式合同确认要求执行以下校验：

- 项目名称：必填；
- 工程合同签订日期：必填；
- 施工单位：必填；
- 建设单位：必填；
- 合同金额：必填且必须大于零；
- 付款条款：新增必填多行文本框，填写合同中的付款节点或支付约定。

付款条款作为基础信息的最后一个合同字段显示，不增加向导步骤。用户点击“下一步”时即执行校验并定位错误，不将缺失问题推迟到最终提交。

### 3.4 合同已上传状态

面板顶部保持紧凑工具栏：

- 文件名和上传状态；
- `更换合同`；
- 上一页、页码输入/总页数、下一页；
- 缩小、缩放比例、放大、适合宽度；
- 折叠面板。

正文只渲染当前页。用户切换页码或缩放时，显示局部骨架屏并保留上一帧，避免整个新建弹窗闪白。预览失败时提供 `重试` 和 `下载原文件`，但不清空左侧表单。

更换合同前弹出确认：新文件上传成功后才替换当前关联；上传失败仍保留旧合同，避免出现既丢文件又丢进度的状态。

## 4. PDF 预览技术方案

前端使用 `pdfjs-dist` 渲染 PDF，而不是浏览器内嵌 iframe 或服务器逐页转图。

### 4.1 加载策略

1. 打开已有关联合同时只请求 PDF 元数据和首屏所需字节。
2. 通过支持 HTTP Range 的原文件接口加载 PDF。
3. 只渲染当前页，并在浏览器空闲时预取前后各一页。
4. 页码快速变化时取消过期渲染任务，旧任务不得覆盖最新页面。
5. 缩放或面板尺寸变化时复用已加载的 PDF 文档，只重绘当前页。
6. 页面离开、弹窗关闭或合同被替换时销毁 canvas、渲染任务和 PDF 文档引用。

预览的加载状态只属于右侧面板。左侧表单初始化、切换步骤和录入不等待 PDF 页渲染。

### 4.2 原文件读取接口

新增鉴权接口：

`GET /api/document-versions/{versionId}/original`

接口行为：

- 复用现有文档归属和项目访问权限校验。
- 返回原始 PDF 的正确 `Content-Type`、`Content-Length`、`Accept-Ranges`。
- 支持标准 `Range` 请求及 `206 Partial Content`，非法范围返回 `416`。
- 不返回服务器文件系统路径。
- 文件不存在、版本不存在或无访问权时返回现有结构化错误。

实现复用服务器已有的文件 Range 响应函数，不新建第二套流式传输实现。

## 5. 手工建档数据流

### 5.1 上传与草稿状态

合同上传继续使用现有不可变文档与版本存储。上传成功后，新建向导保存以下会话状态：

- `documentId`；
- `documentVersionId`；
- 原文件名、大小和 MIME 类型；
- 当前 PDF 页码和缩放比例；
- 现有项目表单值及当前向导步骤。

表单快照和文档版本关联应写入当前用户的建档草稿，以支持关闭弹窗、刷新页面或网络中断后继续。草稿仍按所有人隔离；无合同原件时可以保存进度，但不能生成正式项目。

### 5.2 确认生成

前端在现有“确认生成”按钮触发时提交一个手工合同建档命令。接口固定为：

`POST /api/document-versions/{versionId}/manual-project-confirmation`

请求包含：

- 稳定的 `idempotencyKey`；
- 当前表单版本；
- 由现有向导字段映射得到的合同关键事实；
- 其余项目主档案字段；
- 当前用户草稿 ID（如有）。

合同关键事实继续使用 `contract.v1` 语义键：

| 向导字段 | 合同语义键 |
| --- | --- |
| 项目名称 | `project.name` |
| 建设单位 | `party.owner` |
| 施工单位 | `party.contractor` |
| 合同金额 | `contract.amount` |
| 工程合同签订日期 | `contract.signed_date` |
| 付款条款 | `contract.payment_terms` |
| 项目负责人 | `project.manager` |
| 计划开始日期 | `contract.start_date` |
| 计划完成日期 | `contract.end_date` |

后端应用服务在一个数据库事务中完成：

1. 校验写入权限、文档版本、文件类型、草稿归属和幂等键。
2. 将关键事实记录为 `manual-entry` 且 `human_confirmed` 的合同复核事实；不生成 OCR 文本、坐标或置信度。
3. 执行现有必填字段、金额、日期、重复合同和项目编号校验。
4. 复用合同确认领域写入器，创建项目、合同快照、合同记录、证据关联和生命周期事件。
5. 在同一事务中写入向导里的其他项目主档案字段并初始化资料目录/待办。
6. 将草稿标记为完成并回写新项目 ID。

该接口不是普通项目新增接口：没有可访问的合同原件、关键字段不完整、合同文件已经建档或用户无确认权限时均拒绝。现有 `buildProjectMutationPayload('create')` 门禁继续保留。

### 5.3 字段语义

除新增付款条款并加强建设单位、合同金额的必填校验外，向导原字段保持不变。合同确认写入器当前未覆盖但向导已有的字段（例如联系人、联系电话、我方角色、项目类型、项目地点、已付款金额、结算状态和说明）由手工建档应用服务按白名单写入同一项目记录。客户端不能提交生命周期版本、审计关联 ID、创建人等受保护字段。

第二步继续显示现有只读文案“初始项目状态：已中标”，不改变页面设计。正式生成时，后端依据已经签署并确认的合同事实按现有合同建档规则写入 `contract_signed` 生命周期状态；客户端不能提交或覆盖生命周期状态。确认生成页和创建后的项目详情使用后端返回的实际阶段，不把第二步的说明值当作可写字段。

## 6. 续填与“大洋湾”未完成项目

新流程必须支持传入一个尚未生成正式项目的 `documentVersionId` 来恢复建档：

1. 校验该版本仍存在、当前用户有权访问、且尚未通过相同文件哈希生成项目。
2. 直接在右侧打开原合同，不重新上传、不重新转图。
3. 恢复已有草稿字段；没有草稿字段时打开空白四步向导，由用户继续手工录入。
4. 历史上因超时产生的开放复核记录保留用于审计，不作为新界面的必经步骤，也不得导致重复项目。

上线验收时，用已经上传的“大洋湾小瀛台翻新改造项目”合同版本续接本流程，确认公司名称使用“盐城太悦装配建筑工程有限公司”，且项目列表中不存在同合同重复项目后再生成。

## 7. 错误处理与并发

- PDF 预览失败：左侧仍可填写；可重试或下载原文件。若服务器并未保存原件，确认生成仍被阻断。
- 上传失败：旧合同关联和已填字段保持不变。
- 表单校验失败：仍由现有向导定位字段；右侧页码不重置。
- 合同已被其他请求建档：返回已有项目线索并阻止重复创建。
- 重复点击确认：相同幂等键返回同一创建结果；按钮处于提交中时不可再次触发。
- 网络超时但后端已经成功：重试相同幂等键可取回创建结果，不产生第二个项目。
- 草稿版本冲突：提示数据已在其他窗口更新，先刷新草稿，不静默覆盖。
- 更换合同：新文件成功保存前不解除旧文件关联。

错误提示必须区分“预览加载失败”“合同未保存”“项目确认失败”，避免用户误判项目或文件是否已经创建。

## 8. 权限与审计

- 编辑者和管理员可上传合同、保存自己的建档草稿并确认生成；查看者不可写。
- 原 PDF 下载和 Range 读取执行后端鉴权，不能依靠隐藏 URL。
- 持久记录合同上传/更换、草稿保存、手工事实确认、正式建档和失败原因。
- 日志保存操作人账号 ID 与显示姓名，不保存合同原文副本、密码或临时凭据。
- 未确认生成前不产生正式项目编号、正式项目、合同事实或生命周期事件。

## 9. 组件与代码边界

建议保持以下职责分离：

- `ProjectManagementView.vue`：保留现有向导和步骤控制，只负责组合左右两栏及提交建档命令。
- `ContractPdfPreview.vue`：上传状态、工具栏、PDF.js 文档生命周期、当前页渲染和局部错误。
- `manualProjectIntake.ts`：表单到合同语义键/项目白名单的纯映射、前端请求和幂等键管理。
- 文档 API：原 PDF 鉴权 Range 接口及手工建档路由。
- 手工建档应用服务：权限、草稿、手工复核事实、合同确认事务和附加项目字段写入。
- 现有合同确认领域写入器：继续负责项目、合同、证据快照和生命周期事实的核心一致性。

不把 PDF.js 渲染、业务字段映射和正式建档事务继续堆入现有大型页面文件。

## 10. 测试范围

### 10.1 前端

- 新建入口打开原四步向导，不再打开独立复核工作台。
- 四步名称、顺序、字段、校验和按钮行为保持回归一致。
- 建设单位、合同金额和付款条款在基础信息步骤按后端门禁必填，合同金额必须大于零。
- 新建显示右侧预览，编辑已有项目不显示。
- PDF 只渲染当前页并预取相邻页；快速翻页取消过期任务。
- PDF 加载、缩放、折叠、替换及错误重试不清空表单。
- 未上传成功时“确认生成”给出准确阻断提示。
- 表单字段映射不包含生命周期、审计关联和其他受保护字段。

### 10.2 后端

- 原 PDF 接口的鉴权、`200/206/416`、MIME 类型和不存在场景。
- 手工确认接口的权限、文档归属、必填字段、金额/日期、白名单和草稿归属校验。
- 无合同、非 PDF、重复合同哈希、查看者、未知字段均被拒绝。
- 同一幂等键重复提交返回同一项目；不同键不能绕过重复合同门禁。
- 项目、合同、快照、证据关联、生命周期事件、资料目录和草稿完成要么全部提交，要么全部回滚。
- 手工事实不包含伪造 OCR 文本、坐标或置信度。
- 其余向导项目字段按白名单正确落库，受保护字段不可覆盖。

### 10.3 性能与生产验收

- 用 57 页扫描合同验证：上传后不触发 300 DPI 全量转图或 OCR。
- 首次打开预览不等待所有页下载或渲染；翻到任意页只产生所需 Range 请求。
- 预览过程中左侧输入和步骤切换保持可操作。
- 复用“大洋湾”已上传合同完成一次正式建档，确认施工单位为“盐城太悦装配建筑工程有限公司”。
- 刷新项目列表只出现一个对应项目，合同原件可从项目资料中访问。

## 11. 验收标准

1. 用户点击“手工创建项目”后看到原四步向导，原页面结构和流程未被替换。
2. 同一弹窗右侧可以上传、翻阅、缩放和折叠合同 PDF。
3. 57 页扫描合同不再因同步全量转图造成 60 秒级等待或网关超时。
4. PDF 预览故障不会清空或锁死左侧表单。
5. 未保存合同原件时不能生成正式项目。
6. 所有项目事实均来自用户手工录入，不展示或提交 AI/OCR 建议。
7. 正式建档仍经过合同确认门禁，并原子化生成项目、合同、证据和生命周期事实。
8. 重试或双击不会产生重复项目。
9. 已上传但未完成的合同可以续填，不要求重新上传。
10. “大洋湾”项目以“太悦”公司名称成功生成，且不存在同合同重复项目。
11. 建设单位、合同金额或付款条款缺失时不能离开基础信息步骤，错误定位到对应字段。
