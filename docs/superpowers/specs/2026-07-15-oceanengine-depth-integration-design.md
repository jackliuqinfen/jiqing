# 巨量引擎式 B 端视觉深化设计

## 1. 目标

在不复制第三方品牌资产、不改变工程 ERP 业务逻辑、不引入模拟数据的前提下，提取成熟 B 端工作台的视觉层级并应用到现有 Vue 3 + Arco Design 系统。

本轮重点解决当前页面与参考后台之间仍然明显的细节差异：

- 页面背景只有简单浅蓝到白渐变，缺少前景、环境光和结构纹理的层次。
- 顶部导航、侧栏、查询工具带和业务内容面之间的材质关系不够清晰。
- 卡片虽然统一为白色，但标题、数据、内容和操作区仍缺少一致的层级节奏。
- 全站阴影、边框、透明度和悬浮反馈尚未形成可复用规范。

## 2. 设计边界

### 本轮包含

- 全局页面背景和环境层。
- 平台顶栏、用户区和二级侧栏。
- 页面标题区、统计卡片、查询工具带、业务面板和表格。
- Arco 输入框、按钮、下拉层、弹窗和分页的统一视觉覆盖。
- 桌面宽屏、普通桌面和窄侧栏状态的响应式校验。

### 本轮不包含

- 不修改业务字段、接口、权限、流程和数据模型。
- 不新增示例项目、示例金额或模拟看板数据。
- 不复制巨量引擎的背景图片、Logo、插画、图标资产或专有组件代码。
- 不为追求视觉相似而降低 ERP 表格的信息密度和可读性。

## 3. 视觉结构

全站采用四层结构，禁止所有容器同时使用玻璃效果。

### L0 环境背景层

- 页面底色从顶部冷淡蓝过渡到中部灰蓝白，再落到纯白。
- 在顶部 320px 内叠加低对比度斜向细纹，纹理透明度不超过 0.035。
- 使用左上到右上的轻微冷色环境光，不使用独立渐变球、光斑或高饱和装饰。
- 页面滚动时背景固定，避免不同模块出现断层。

建议令牌：

```css
--workspace-bg-top: #eaf4ff;
--workspace-bg-mid: #f4f8fd;
--workspace-bg-bottom: #ffffff;
--workspace-grid: rgba(50, 100, 190, 0.026);
```

### L1 平台导航层

- 顶栏为半透明白色，使用 14px 背景模糊和 0.72 至 0.82 的白色透明度。
- 顶栏底部只保留极浅分割线和环境阴影，不使用完整胶囊外框包裹全部模块。
- 当前模块使用文字加底部指示条，悬浮仅增加轻微蓝色表面。
- 用户区采用头像、欢迎语、姓名三级信息，不与设置和退出按钮混成一组。
- 左侧二级导航使用透明底；选中项为白色承载面、左侧蓝色指示条和极浅阴影。

### L2 数据控制层

- 页面标题区保持透明，让背景层可见。
- 统计卡片、查询工具带和数据状态条使用半透明浅白表面。
- 统计卡片通过 1px 顶部或左侧状态色区分业务语义，不用大面积彩色填充。
- 查询工具带使用连续布局，控件之间通过间距和尺寸分组，不堆叠多层卡片。
- 允许 `backdrop-filter`，但仅限这一层和平台导航层。

### L3 业务承载层

- 台账、表格、看板列、表单、弹窗和详情面板使用不透明白色。
- 表头使用 `#f6f8fb`，表格边界使用 `#e6ebf3`，行悬浮使用 `#f7faff`。
- 业务卡片不使用背景模糊，避免文字和长表格失去清晰度。
- 面板标题、辅助说明和操作区采用固定 16/12/14px 文字层级。

## 4. 组件令牌

### 圆角

- 页面面板、统计卡片、表格容器：8px。
- 输入框、按钮、标签、分页：6px。
- 头像和数字计数器：圆形。
- 禁止同一层同时出现 4px、8px、12px、16px 四种圆角。

### 边框

```css
--border-subtle: rgba(211, 222, 236, 0.78);
--border-solid: #e2e8f2;
--border-strong: #cad7e8;
```

### 阴影

```css
--shadow-ambient: 0 4px 16px rgba(31, 64, 108, 0.045);
--shadow-card: 0 8px 24px rgba(31, 64, 108, 0.065);
--shadow-float: 0 16px 40px rgba(25, 54, 96, 0.13);
```

- 默认面板使用环境阴影。
- 可点击统计卡片和主操作按钮使用卡片阴影。
- 下拉层、弹窗和抽屉使用浮层阴影。
- 禁止所有组件共用同一强阴影。

### 颜色

- 主色继续使用系统现有蓝色，不替换品牌色。
- 成功、预警、危险和信息状态只用于数字、标签、边线或小面积图标。
- 大面积页面背景不使用高饱和蓝、紫色或青色渐变。

## 5. 关键页面规则

### 工作台

- 工作台头部采用两层关系：透明标题层 + 半透明数据摘要层。
- 指标卡片保持等高，金额字段允许两行显示，不压缩中文大写金额。
- 图表面板使用白色实体面，避免图表网格与背景纹理相互干扰。

### 项目管理与审计

- 筛选区为数据控制层，看板列和项目卡片为业务承载层。
- 看板列标题可使用 2px 状态色顶边，列体保持白色或极浅灰白。
- 项目卡片数量较多时保留项目名称、单位和金额的紧凑展示，不改变业务自适应规则。

### 资料、招投标、结算与后台

- 头部、工具带和实体数据区之间保持 16px 真空间距，不使用蓝色填充连接。
- 空状态保持真实，不生成模拟记录。
- 配置表格优先保证字段名称、关联项和操作列可读，不因装饰导致列宽压缩。

## 6. 交互状态

- 悬浮：仅改变边框、浅背景或阴影，不移动组件位置。
- 聚焦：使用主色 1px 外描边和低透明度光晕，不能改变控件尺寸。
- 加载：骨架和加载状态保持原容器稳定尺寸。
- 禁用：降低文字与边框对比度，但仍需满足基本可识别性。
- 侧栏拖拽线默认不可见，悬浮和拖拽时使用与环境阴影接近的浅色提示。

## 7. 响应式

- `>= 1280px`：顶栏完整展示，侧栏展开，内容维持紧凑网格。
- `900px - 1279px`：顶栏模块名称可缩短，统计卡片允许换行，侧栏进入窄栏。
- `< 900px`：侧栏作为覆盖式导航，页面单列，顶部操作进入菜单。
- 所有固定格式控件需设置稳定宽高，切换状态不得推动周围布局。

## 8. 验收标准

1. 顶部 500px 范围内能看出蓝到白的三段环境层，但正文区域接近白色。
2. 顶栏、统计卡片和查询工具带存在轻微透明层次；表格和正文面板保持纯白清晰。
3. 任一页面不出现卡片之间的蓝色实心填充、虚线外框或强渐变按钮。
4. 平台顶栏、二级侧栏、页面 Tab 职责清楚，当前路径不重复显示。
5. 项目、审计、资料、招投标、结算和后台页面在 1560×960 下无文字溢出和控件重叠。
6. 侧栏展开、窄栏和隐藏状态切换时，文字、按钮和拖拽线不变形。
7. `npm run build` 通过，关键页面完成同视口截图检查。

## 9. 实施策略

- 优先修改全局设计令牌和 `arco-premium-workbench.css`，避免在业务组件中散落新样式。
- 仅在全局样式无法表达结构时修改 `AppLayout.vue`。
- 每完成一个视觉层级即检查工作台、项目、审计和后台四个代表页面。
- 保留现有业务逻辑和真实空状态，视觉优化不得伪造数据。
